# Feature Matrix

**Legend:** P0 essential foundation; P1 first commercially usable release; P2 advanced/premium; Future expansion. Status reflects this repository only.

| Feature | Priority | Purpose / roles | Inputs → outputs | Data / API / screens | Permissions, validation and failure handling | Acceptance / test focus | Complexity | Status |
|---|---|---|---|---|---|---|---|---|
| Public website | P0 | Explain product; all visitors | Route/content → clear product overview | Web pages; public API not required | Public content; responsive and route fallback | All public routes navigate; viewport and keyboard review | M | Complete and tested (frontend gate) |
| Course discovery preview | P0 | Show learning catalog; visitors/students | Search, level → filtered sample cards | Future Course, Category, Educator; GET `/api/v1/courses`; course page | Published course visibility; validate query/filter; empty state | Search/filter/empty state | M | Implemented with clearly labelled sample data |
| Enquiry | P0 | Gather prospective user needs | Contact fields/consent → persisted enquiry and optional email notice | ContactEnquiry; POST `/api/v1/enquiries`; contact form | Public endpoint throttled; validate details and consent; honeypot drops bots; API errors shown | Valid submissions persist; invalid consent rejected; notification status is explicit | M | Partially implemented: API persistence and optional email notification; staff inbox and retention workflow remain |
| Identity and organization context | P0 | Secure user access across tenants | Credentials, MFA, membership → authenticated context | User, Org, Membership; `/auth/*`, `/api/v1/me`, `/api/v1/organizations`; auth/select org UI | Policies, role checks, rate limiting; generic auth errors | Current-user auth and organization membership isolation covered; registration/login/recovery pending | L | Partially implemented: Sanctum guard and membership-scoped list; auth flows/policies pending |
| Organization/academic masters | P0 | Configure academic operations; admins and management | Session/class/subject inputs → organization records | Organization, Session, Class, Section, Subject; `/organizations/{id}/academic-sessions`, `/classes`, `/subjects` | Active membership required; writes restricted to admin, management, or independent educator; unique names/codes and valid dates | Create/list/update, session selection, role restriction, tenant isolation | L | Partially implemented: API and admin dashboard create/list/archive flows for sessions, classes, sections, subjects; PostgreSQL validation and richer edit workflows remain |
| People and roles | P0 | Maintain learners/staff; admins | Profile inputs → organization roster records | Student, Teacher, StudentGuardian, TeachingAssignment, Membership, OrganizationInvitation; roster, invitation, `/my/student`, `/my/children` APIs | Admin/management/independent-educator role; student invitations require matching active roster; parent invitation selects active children; tenant-scoped profiles | Create/search/update status, invitation expiry/revoke/accept, account link scope and tenant isolation | L | Partially implemented: rosters, assignments, staff/student/parent invitations, student and guardian links; direct link management and consent/retention workflows remain |
| Attendance and schedule | P1 | Coordinate teaching and participation | Date, section, status, weekly slot → register and timetable | AttendanceRecord, TimetableEntry; `/organizations/{id}/attendance`, `/timetable` | Verified admin/management/independent educator access; teachers require a linked profile and assignment to the section/session; active student placement; session dates; duplicate upsert and schedule overlap checks | Batch mark/update; teacher scope isolation; section/teacher/room conflict detection | M/L | Partially implemented: admin and assigned teacher attendance screens use persistent APIs; timetable teacher schedule visibility is scoped; reports remain |
| Courses, lessons, materials | P0 | Deliver structured learning; teachers/students | Course details, lesson text, private uploads → published learning content and student completion | Course, Lesson, Enrollment, CourseAsset, CourseLessonProgress; `/courses`, `/courses/{course}/lessons`, `/progress`, `/assets`, `/enrollments` | Organization member; managers/linked teachers author; enrolled students read content and change only their own completion; allow-listed file type/size; downloads re-authorized | Draft/publish lifecycle, linked teacher scope, enrollment isolation, lesson visibility, completion percentage, private storage and download controls | L | Partially implemented: course drafts/lessons/enrollment, private file upload/download, and student lesson completion; modules, staff progress reports, malware scanning/retention and durable long-term storage remain; assignments/assessments are tracked separately |
| Live and management meetings | P1 | Connect classes and staff | Time, organizer, attendees, link → schedule/detail | Meeting, Participant; `/meetings`; Meet provider/manual URL | Authorized participants, valid URL/time; provider failure permits manual entry | Correct visibility and link behavior | M | Not started |
| Assignments and exams | P1 | Practice and assess learning | Prompt, due date, text submission, score/feedback → reviewed work | CourseAssignment, AssignmentSubmission; course assignments, submissions, grade APIs | Course managers/linked teachers publish and grade; enrolled students submit only to their published courses; score capped at assignment maximum | Draft/publish, enrollment isolation, resubmission, grade scope and score integrity | L | Partially implemented: assignment authoring, student text submission, teacher grading and feedback; timed MCQ quizzes, auto-scored attempts, and per-quiz student/instructor history are implemented; broader examinations and result reporting remain |
| Reports and notifications | P1 | Surface academic status and reminders | Date range → attendance totals/rates by class and section | AttendanceRecord; `GET /organizations/{id}/reports/attendance`; future notifications API | Active organization admin, management or independent educator; tenant-scoped date/session filters; invalid ranges rejected | Aggregate scope, period filtering, status counts and empty results | M/L | Partially implemented: attendance summary API and dashboard; other academic reports and notifications remain |
| Fee records/payment | P1 | Track finance and future collection | Invoice/manual receipt/sandbox event → ledger/status | Fee, Invoice, Payment, Webhook; `/fees`, `/payments` | Finance role; idempotency; sandbox only initially | Webhook retry and amount/state validation | L | Not started |
| AI assistance | P2 | Optional teaching/learning help | Prompt/authorized context → draft explanation/questions | AI usage/config; `/ai/*` | Rate/cost limits, moderation, no auto-grading, provider failure fallback | Safety, authorization and quota behavior | L | Not started |
| Mobile apps | P1 after web | Essential mobile workflows; teachers/students/admin | API actions → synced app views | Shared API, React Native clients | API policies remain authoritative | Android/iOS workflow/device tests | L | Not started |
| Subscriptions and entitlements | Future/P2 | Monetize later | Plan and usage → entitlements/billing | Plan, Entitlement, Usage, Subscription | Disabled until commercial approval/configuration | Feature limits and billing sandbox | L | Not started |

Complexity: S small, M medium, L large. Only routes listed as implemented in `docs/API_SPECIFICATION.md` are operational. Each feature's detailed failure and acceptance criteria are refined before implementation.
