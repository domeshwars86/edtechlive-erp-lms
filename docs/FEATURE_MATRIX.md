# Feature Matrix

**Legend:** P0 essential foundation; P1 first commercially usable release; P2 advanced/premium; Future expansion. Status reflects this repository only.

| Feature | Priority | Purpose / roles | Inputs → outputs | Data / API / screens | Permissions, validation and failure handling | Acceptance / test focus | Complexity | Status |
|---|---|---|---|---|---|---|---|---|
| Public website | P0 | Explain product; all visitors | Route/content → clear product overview | Web pages; public API not required | Public content; responsive and route fallback | All public routes navigate; viewport review; first-tab skip link and single main landmark keyboard check | M | Complete and tested (frontend gate) |
| Dashboard overview summaries | P0 | Show relevant real activity to all signed-in roles | Organization context → role-scoped rosters, schedules, learning, assignments, attendance, and family data | Student, StudentGuardian, Teacher, TimetableEntry, AttendanceRecord, CourseEnrollment, CourseLessonProgress, CourseAssignment, Meeting; `GET /organizations/{id}/dashboard/summary`, `GET /organizations/{id}/dashboard/activity`; platform overview, organization/user directory and status audit APIs | Role-specific response shape; tenant and profile scopes; parent visibility only through explicit student links; organization timezone; no marks yields no rate instead of zero; platform actions require verified allowlist and reasoned audit | Cross-tenant isolation, role denial, profile scope, local date windows, schedule/review/attendance aggregation, suspension access revocation/restoration, audit visibility | M | Role-specific cards, seven-day activity totals and upcoming meeting panel use live, scoped APIs for admin, management, independent educator, teacher, student and parent. The allowlisted super-admin overview and CSV platform snapshot use live aggregates; operators can search directories, suspend/reactivate organizations and ordinary user accounts with reasons, and review paginated status audit history. |
| Public course discovery | P0 | Show learning catalog; visitors/students | Search, level, subject → paginated public listings and published lesson outline | `Course.slug`, `Course.is_public_listing`; public catalog/detail API; `/courses`, `/courses/{organizationSlug}/{courseSlug}` | Only active organizations, explicitly listed published courses, and published lessons; response excludes internal IDs, teacher profiles, lesson content/assets, and enrollment data; rate-limited | API privacy/publication/filter/pagination tests, browser catalog/detail flow, responsive empty/error states | M | Implemented API-backed catalog and detail pages with search, filters, pagination and explicit course-editor opt-in. | Identity and organization context | P0 | Secure user access across tenants | Credentials, email verification, membership → authenticated context | User, Organization, Membership, MembershipPermission, OrganizationAccessAudit, PlatformAuditEvent; `/auth/*`, `/api/v1/me`, `/api/v1/me/profile`, `/api/v1/organizations`, membership and platform user-access routes; auth/select org UI | Sanctum session/token auth, verified membership, rate limits; tenant-scoped membership read/manage/audit capabilities; profile edits require current password; optional password changes require strong confirmation and revoke other API tokens; changed emails require fresh verification; platform operator allowlist addresses cannot be claimed or changed through self-service; permission grants limited to admin/independent educator; loss of last privileged manager is rejected and audited | Registration, sign-in, verification resend, recovery, profile update/reverification, password change/token revocation, current-user, delegated membership workflows, permission grants, account suspension/reinstatement, audit, tenant isolation, and keyboard navigation to the account form | L | Partially implemented: connected registration/login/verification/recovery and membership chooser; web and Expo users can update their own name/email and optionally change their password with current-password confirmation, confirmed strong password, and revocation of other Sanctum API tokens; changed emails require fresh verification; admins/independent educators can manage membership roles/status and grant catalog overrides; Management defaults to membership read; delegated membership managers have role escalation and privileged-target limits; platform operators can suspend/reactivate ordinary accounts with reasoned audit and global endpoint enforcement. These capabilities currently cover membership workflows only; other domain policies still use role/resource checks. MFA and generic cross-domain policy configuration remain |
| Organization/academic masters | P0 | Configure academic operations; admins and management | Workspace name/timezone, branch, sessions/classes/sections/batches/subjects → organization records | Organization, OrganizationBranch, Session, Class, Section, Batch, Subject; `/organizations/{id}/settings`, `/branches`, `/academic-sessions`, `/classes`, `/sections`, `/batches`, `/subjects` | Active membership required; settings writes limited to admin/independent educator; academic writes restricted to admin, management, or independent educator; branch, batch, class, section, and session placement consistency; unique names/codes, valid timezone and ordered dates | Branch assignment, batch create/list/edit/search/filter/activate, role restriction and tenant isolation; update workspace settings; academic master CRUD/status flows | L | Partially implemented: admin and independent educator can update workspace name/timezone; academic masters support create/list/edit/archive/restore for sessions, classes, sections and subjects, plus branch assignment and searchable/filterable batch management; validated on disposable PostgreSQL 17; hosted PostgreSQL 16 CI remains |
| People and roles | P0 | Maintain learners/staff; admins | Profile inputs → organization roster records | Student, Teacher, StudentGuardian, TeachingAssignment, Membership, OrganizationInvitation; roster, guardian management, invitation, `/my/student`, `/my/children` APIs | Admin/management/independent-educator role; student invitations require matching active roster; direct parent links require an active verified parent membership in the same tenant | Create/search/edit/update status, paginated CSV browsing/export and field-level preview with explicitly selected updates; invitation expiry/revoke/accept, guardian link/unlink, primary contact uniqueness and tenant isolation | L | Partially implemented: stable paginated branch-aware student/teacher roster browsing with create/edit/search/filter/status actions, formula-safe CSV export, and field-level CSV reconciliation by admission/employee number with a review preview and selected updates; matching is tenant-scoped, status changes are opt-in, unmatched/duplicate rows are skipped, updates never create/delete records, and uploads are limited to 500 rows/2 MB; teaching assignments, staff/student/parent invitations, and direct student/guardian link management; consent/retention workflows remain |
| Attendance and schedule | P1 | Coordinate teaching and participation | Date, section, status, weekly slot → register, reasoned correction history and timetable | AttendanceRecord, AttendanceCorrection, TimetableEntry; `/organizations/{id}/attendance`, `/attendance/corrections`, `/timetable` | Verified admin/management/independent educator access; teachers require a linked profile and assignment to the section/session; active student placement; session dates; saved mark changes require a reason and append actor/before/after audit; duplicate upsert and schedule overlap checks | Batch mark/update; teacher scope isolation; correction reason and rollback-on-invalid update; section/teacher/room conflict detection | M/L | Partially implemented: admin and assigned teacher attendance screens use persistent APIs; changing a saved mark or note requires a reason and appears in section/date-scoped correction history; management and other authorized reporting roles can view date-filtered attendance reports with CSV export; timetable teacher schedule visibility is scoped |
| Courses, lessons, materials | P0 | Deliver structured learning; teachers/students | Course details, module sequence, lesson text, private uploads → published learning content and student completion | Course, CourseModule, Lesson, Enrollment, CourseAsset, CourseLessonProgress; `/courses`, `/courses/{course}/modules`, `/courses/{course}/lessons`, `/progress`, `/assets`, `/enrollments` | Organization member; managers/linked teachers author and review scoped progress; enrolled students read published modules and lessons and change only their own completion; allow-listed file type/size; downloads re-authorized | Draft/publish lifecycle, linked teacher scope, enrollment isolation, module/lesson ordering, student visibility, completion percentage, private storage and download controls | L | Partially implemented: ordered module creation/editing, lesson grouping, course enrollment, private file upload/download, student completion, and course-scoped progress review; organization-wide reports, malware scanning/retention and durable long-term storage remain; assignments/assessments are tracked separately |
| Live and management meetings | P1 | Connect classes and staff | Time, organizer, group, secure provider link, consent-attested recording → scoped schedule and replay | Meeting, MeetingRecording, GoogleMeetConnection; `/organizations/{id}/meetings`, `/meetings/{meeting}/recordings`, `/meetings/google/*`; admin, teacher and family dashboards | Admin/management schedule; teachers require assignment and can manage recordings only for meetings they created; students and parents see only enrolled/linked groups and published recordings; HTTPS only; class overlaps rejected; uploads stay private; Google OAuth connection belongs to the authorized organizer and tenant | Role and tenant scope, assignment scope, one-time OAuth state, encrypted tokens, token refresh, overlap detection, file/link validation, consent attestation, publication and withdrawal, authenticated downloads | M/L | Partially implemented: manual HTTPS class/management meetings and scoped recordings; optional Google OAuth room creation is available when configured, with connection status, token refresh and disconnect. No Meet capture, participant invitations, attendance sync, reminders, retention purge or durable cloud storage configuration. Live Google setup remains unverified. |
| Assignments and exams | P1 | Practice and assess learning | Prompt, due date, text submission, score/feedback; scheduled objective and written-response quizzes; institution exam schedule, sectional paper, roster result and publication | CourseAssignment, AssignmentSubmission, CourseQuestionBank, CourseQuestionBankQuestion, CourseQuiz, QuizQuestion, QuizAttempt, AcademicExam, AcademicExamPaper, AcademicExamPaperSection, AcademicExamResult, AcademicExamSectionResult; question-bank/quiz/attempt APIs and `/exams` | Course managers/linked teachers author/reuse course questions and review written answers; enrolled students submit only to published courses and within quiz windows; school exam teachers need exact section/session/subject assignment; family results require publication and guardian links | Draft/publish, bank course scope, no duplicate/cross-course import, exact-set scoring, answer-key privacy, review-state privacy, opening/closing windows, attempt/time limits, score caps, full-roster coverage, section maximums equal paper maximum, section scores sum to total, immutable published marks | L | Implemented: assignment authoring, student text submission, teacher grading/feedback; editable searchable course-scoped question banks with paginated questions and snapshot import into draft quizzes; scheduled single-choice/multiple-select quizzes with difficulty, server scoring, proportional negative marking, optional pass threshold, time/attempt limits and paginated history; written-response quizzes with course-editor grading, feedback, partial/final scores, pending-review tracking and averages that exclude unreviewed attempts; institution exam schedules, subject papers with optional named/scored sections, per-section marks, teacher mark entry, absent/excused outcomes, roster-complete publication and family-visible score breakdowns; optional exam-series labels and tenant-scoped cross-exam comparisons with teacher assignment filtering and CSV export |
