# Feature Matrix

**Legend:** P0 essential foundation; P1 first commercially usable release; P2 advanced/premium; Future expansion. Status reflects this repository only.

| Feature | Priority | Purpose / roles | Inputs → outputs | Data / API / screens | Permissions, validation and failure handling | Acceptance / test focus | Complexity | Status |
|---|---|---|---|---|---|---|---|---|
| Public website | P0 | Explain product; all visitors | Route/content → clear product overview | Web pages; public API not required | Public content; responsive and route fallback | All public routes navigate; viewport and keyboard review | M | Complete and tested (frontend gate) |
| Dashboard overview summaries | P0 | Show relevant real activity to all signed-in roles | Organization context → role-scoped rosters, schedules, learning, assignments, attendance, and family data | Student, StudentGuardian, Teacher, TimetableEntry, AttendanceRecord, CourseEnrollment, CourseLessonProgress, CourseAssignment, Meeting; `GET /organizations/{id}/dashboard/summary`, `GET /organizations/{id}/dashboard/activity` | Role-specific response shape; tenant and profile scopes; parent visibility only through explicit student links; organization timezone; no marks yields no rate instead of zero | Cross-tenant isolation, role denial, profile scope, local date windows, schedule/review/attendance aggregation, empty states | M | Role-specific cards, seven-day activity totals and upcoming meeting panel use live, scoped APIs for admin, management, independent educator, teacher, student and parent; the chart displays lesson completions and assignment submissions, not estimated study hours. Platform super-admin metrics are illustrative; live timetable/notification panels cover upcoming classes and recent family updates |
| Course discovery preview | P0 | Show learning catalog; visitors/students | Search, level → filtered sample cards | Future Course, Category, Educator; GET `/api/v1/courses`; course page | Published course visibility; validate query/filter; empty state | Search/filter/empty state | M | Implemented with clearly labelled sample data |
| Enquiry | P0 | Gather prospective user needs | Contact fields/consent → persisted enquiry and optional email notice | ContactEnquiry; POST `/api/v1/enquiries`; contact form | Public endpoint throttled; validate details and consent; honeypot drops bots; API errors shown | Valid submissions persist; invalid consent rejected; notification status is explicit | M | Implemented: throttled consented intake, optional email, allowlisted operator inbox, search/status filters, status tracking with reviewer audit; automated retention remains |
| Identity and organization context | P0 | Secure user access across tenants | Credentials, email verification, membership → authenticated context | User, Organization, Membership; `/auth/*`, `/api/v1/me`, `/api/v1/organizations`; auth/select org UI | Sanctum session/token auth, verified membership, rate limits; safe validation/auth errors | Registration, sign-in, verification resend, recovery, current-user and tenant membership isolation | L | Partially implemented: registration/login/verification/recovery and dashboard membership chooser are connected and covered by API tests; selection is held in the frontend session, with persistent active-org preference, MFA and broader audit/policy controls open |
| Organization/academic masters | P0 | Configure academic operations; admins and management | Session/class/subject inputs → organization records | Organization, Session, Class, Section, Subject; `/organizations/{id}/academic-sessions`, `/classes`, `/subjects` | Active membership required; writes restricted to admin, management, or independent educator; unique names/codes and valid dates | Create/list/update, session selection, role restriction, tenant isolation | L | Partially implemented: API and admin dashboard create/list/archive flows for sessions, classes, sections, subjects; PostgreSQL validation and richer edit workflows remain |
| People and roles | P0 | Maintain learners/staff; admins | Profile inputs → organization roster records | Student, Teacher, StudentGuardian, TeachingAssignment, Membership, OrganizationInvitation; roster, guardian management, invitation, `/my/student`, `/my/children` APIs | Admin/management/independent-educator role; student invitations require matching active roster; direct parent links require an active verified parent membership in the same tenant | Create/search/update status, invitation expiry/revoke/accept, guardian link/unlink, primary contact uniqueness and tenant isolation | L | Partially implemented: rosters, assignments, staff/student/parent invitations, and direct student/guardian link management; consent/retention workflows and roster reconciliation remain |
| Attendance and schedule | P1 | Coordinate teaching and participation | Date, section, status, weekly slot → register and timetable | AttendanceRecord, TimetableEntry; `/organizations/{id}/attendance`, `/timetable` | Verified admin/management/independent educator access; teachers require a linked profile and assignment to the section/session; active student placement; session dates; duplicate upsert and schedule overlap checks | Batch mark/update; teacher scope isolation; section/teacher/room conflict detection | M/L | Partially implemented: admin and assigned teacher attendance screens use persistent APIs; timetable teacher schedule visibility is scoped; reports remain |
| Courses, lessons, materials | P0 | Deliver structured learning; teachers/students | Course details, module sequence, lesson text, private uploads → published learning content and student completion | Course, CourseModule, Lesson, Enrollment, CourseAsset, CourseLessonProgress; `/courses`, `/courses/{course}/modules`, `/courses/{course}/lessons`, `/progress`, `/assets`, `/enrollments` | Organization member; managers/linked teachers author and review scoped progress; enrolled students read published modules and lessons and change only their own completion; allow-listed file type/size; downloads re-authorized | Draft/publish lifecycle, linked teacher scope, enrollment isolation, module/lesson ordering, student visibility, completion percentage, private storage and download controls | L | Partially implemented: ordered module creation/editing, lesson grouping, course enrollment, private file upload/download, student completion, and course-scoped progress review; organization-wide reports, malware scanning/retention and durable long-term storage remain; assignments/assessments are tracked separately |
| Live and management meetings | P1 | Connect classes and staff | Time, organizer, group, secure provider link → scoped schedule/details | Meeting; `GET/POST/PATCH /organizations/{id}/meetings`; admin, teacher, student, parent screens | Admin/management schedule; teachers require assignment; students and parents see only enrolled/linked groups; HTTPS only; class overlaps rejected | Role scope, assignment scope, overlap detection, cancellation, private links | M/L | Partially implemented: manual HTTPS class and management meetings; provider room creation, reminders, participant invites and recording uploads remain |
| Assignments and exams | P1 | Practice and assess learning | Prompt, due date, text submission, score/feedback → reviewed work | CourseAssignment, AssignmentSubmission; course assignments, submissions, grade APIs | Course managers/linked teachers publish and grade; enrolled students submit only to their published courses; score capped at assignment maximum | Draft/publish, enrollment isolation, resubmission, grade scope and score integrity | L | Partially implemented: assignment authoring, student text submission, teacher grading and feedback; timed MCQ quizzes, auto-scored attempts, and per-quiz student/instructor history are implemented; broader examinations and result reporting remain |
| Reports and notifications | P1 | Surface academic status and reminders | Date range → attendance totals/rates; learner placement/enrollment → section totals; active session assignments → teacher workload and scheduled hours; published courses → learner completion, quiz outcomes and assignment grading backlog; fee ledger → issued, received, outstanding and overdue summaries; fee and meeting events → private in-app notices | AttendanceRecord, Student, CourseEnrollment, TeachingAssignment, TimetableEntry, FeeRecord, FeePayment, CourseQuiz, QuizAttempt, CourseAssignment, AssignmentSubmission, course progress, notifications; `/reports/attendance`, `/reports/enrollment`, `/reports/workload`, `/reports/finance`, `/reports/assessments`, `/reports/course-progress`, `/notifications`; dashboard bell and academic reports | Membership-scoped reports; organization-wide reports are restricted to admin, management and independent educator roles; teachers are limited to owned courses for course progress and assessment outcomes; notification recipient and organization are enforced | Aggregate filters, active session windows, learner deduplication, financial cent rounding, teacher/tenant isolation, notification isolation and read receipts | M/L | Partially implemented: attendance, course placement, teacher workload, finance, course progress, quiz outcome and assignment grading summaries plus scoped in-app notifications for fee and meeting events; cash flow reports, email/push, announcements and preferences remain |
| Fee records/payment | P1 | Track finance and future collection | Student, fee title, INR amount, due date, staff-recorded receipts → balance/status | FeeRecord, FeePayment; `GET/POST /fees`, `POST /fees/{id}/payments`; admin/family fee screens | Tenant-scoped managers issue fees/record payments; students and explicitly linked parents read only; overpayment rejected under row lock | Partial/final receipt totals, overpayment rejection, tenant isolation, parent/child scope | L | Partially implemented: manual fee ledger and family read-only views; payment gateway, idempotency keys, refunds, finance-specific role, and reconciliation reports remain |
| AI assistance | P2 | Optional teaching/learning help | Prompt/authorized context → draft explanation/questions | AI usage/config; `/ai/*` | Rate/cost limits, moderation, no auto-grading, provider failure fallback | Safety, authorization and quota behavior | L | Not started |
| Mobile apps | P1 after web | Essential mobile workflows; teachers/students/admin | API actions → synced app views | Expo React Native app in `apps/mobile`; shared API | Sanctum bearer token in SecureStore; API policies remain authoritative | Android/iOS workflow/device tests | L | Partially implemented: sign-in and verification-link resend, secure token restore/logout, organization selection, scoped summaries, courses/lessons, student and parent profile/attendance/fee views, learner submissions/quizzes/results, notification read receipts, teacher attendance/grading, and scoped meetings; device builds and store readiness remain |
| Subscriptions and entitlements | Future/P2 | Monetize later | Plan and usage → entitlements/billing | Plan, Entitlement, Usage, Subscription | Disabled until commercial approval/configuration | Feature limits and billing sandbox | L | Not started |

Complexity: S small, M medium, L large. Only routes listed as implemented in `docs/API_SPECIFICATION.md` are operational. Each feature's detailed failure and acceptance criteria are refined before implementation.
