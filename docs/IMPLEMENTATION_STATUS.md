# Implementation Status

**Updated:** 19 November 2026

## Current milestone

Phase 10 — mobile applications, initial vertical slice. The responsive public website, seven role dashboards, Laravel ERP/LMS APIs and connected web workflows are in place. The Expo client signs into the shared API, offers verification-link resend, stores its Sanctum token with SecureStore, selects organization membership, and provides role-scoped summaries, Admin/Management active student and teacher overviews, courses/lessons, student/parent profile, attendance, homework, course-progress and assessment-result views (including published school exam results), read-only fee records, published study materials opened through short-lived signed links, student assignment submissions, teacher grading, timed quiz attempts/results, recent notification read receipts, assignment-scoped teacher attendance, and upcoming scoped meeting links that can be joined only during the scheduled window. Native device builds remain open. The latest **132-test / 1,075-assertion** API suite passes on in-memory SQLite. Hosted PostgreSQL 16 CI, verification email delivery, external integrations and deployment remain unverified.

## Implemented

- Responsive, statically pre-rendered public website and all seven role dashboard previews.
- Laravel 13.43 API with Sanctum session/token authentication, throttled registration/login/recovery, signed email verification, password reset and membership-scoped organization reads.
- User, organization and membership models/migrations; organization registration creates an initial active membership transactionally.
- Web client API helper uses credentialed Fetch, Laravel CSRF cookies, and same-origin Vite proxy configuration for local development.
- Login session is restored from `/api/v1/me`; logout calls API; registration, forgot/reset password and resend verification invoke the corresponding API endpoints.
- In local development, registration and resend-verification responses include a short-lived signed verification URL rendered as a clickable link in the auth screen. This response field is only enabled under `APP_ENV=local`; production still requires configured email delivery. Password-reset messages are logged by Laravel's local mailer.
- Organization selection is loaded from active memberships and the API now persists the user's preferred organization. The authenticated web client restores that organization on reload; the save endpoint revalidates active membership and organization status. Connected dashboard headers use the account and organization from API state; role-specific summaries use scoped APIs, and the platform overview uses live aggregates for verified emails on the separate `PLATFORM_ADMIN_EMAILS` allowlist.
- Tenant-scoped academic session, class, section, and subject migrations, models, and API routes are implemented. Active organization members can read; admin, management, and independent educator roles can create/update. Cross-tenant references are rejected.
- The admin dashboard includes create/list/archive flows for sessions, classes, sections, and subjects, backed by the Laravel API.
- Admins, management, and independent educators can manage academic batches tied to a tenant-owned session and class, with an optional matching section. The admin Academic masters page supports create/edit/deactivate/activate, case-insensitive search, session/class/status filters, and pagination. Server validation enforces placement consistency and tenant boundaries.
- Latest verified regression: 132 Laravel tests / 1,075 assertions passed on in-memory SQLite; Pint, web typecheck, ESLint, and production build passed. The web build prerendered 14 routes with a 488.56 kB main bundle. Local SQLite migrations are applied. PostgreSQL verification for the latest migrations remains open.
- Admin and independent-educator Settings pages can update their organization name and IANA timezone; management and other roles cannot change these workspace-level settings.
- The management “Teachers & students” page now switches between tenant-scoped student and teacher rosters backed by the existing role-checked APIs.
- Admins and management can create, search, and activate/deactivate tenant-owned student and teacher roster profiles; student placement references are checked against organization-owned classes, sections, and sessions.
- The admin workspace can take and update paginated daily attendance registers for active students in a section/session, constrained to session dates. It can create, list, and deactivate weekly timetable entries with section/session checks, HTTPS meeting links, and overlap detection.
- Admins can assign active teachers to subject/section/session combinations; timetable entries with a teacher require the matching assignment.
- Admins and management can send, list, and revoke organization invitations. Seven-day, one-time tokens are hashed in storage; new invitees create verified accounts, existing invitees confirm their password or accept while signed in, and teacher profiles are linked or created.
- Teachers can read only their linked teaching assignments and timetable entries. They can take attendance only for assigned sections and sessions through the teacher workspace.
- Student invitations require an active matching roster profile and link the accepted account to it. Parent invitations identify active students to link; parent views expose only those explicit links.
- Admins, management, and independent educators can review, create, designate a primary contact for, and remove student/guardian links. Direct links require an active, verified parent membership within the same organization.
- Admin, management, and independent educator can view a date-filtered attendance report with organization-scoped totals and class/section breakdowns in the dashboard.
- Admin, management, and independent educator can view active student placement by academic session and section, unassigned learner totals, active enrollments in published courses, and a teacher workload report with active session section assignments, distinct active learners, weekly timetable slots and hours. The reports are tenant-scoped and deny teacher access to organization-wide counts.
- Admin, management, independent educator, and course-owning teachers can view published-course progress summaries; teacher reports are restricted to their own courses and omit individual learner identity.
- Attendance, course progress, enrollment placement, teacher workload, quiz/assignment outcomes, published school exam performance, and finance summaries can export their currently authorized report data as UTF-8 CSV. The shared exporter quotes CSV fields and neutralizes spreadsheet formula prefixes.
- Authenticated admin and management dashboard cards use tenant-scoped active student/teacher counts, today's active timetable slots, and today's attendance summaries calculated in the organization timezone. Independent educators see published courses, unique enrolled learners, pending grading and upcoming live classes. Teacher cards count only the teacher's active assignments, linked learners, pending grading in their own courses, and assigned timetable slots for the week. Student cards use that student's active enrollments, recently completed lessons, outstanding assignments, and 30-day attendance only. Parent cards aggregate only explicitly linked active children and their outstanding assignments, attendance, and upcoming meetings. Missing attendance is shown as no rate, not 0%.
- Managers and linked teachers can create draft courses, publish lessons with written content or an external HTTPS resource, upload private course files, publish assignments, review submissions, and author scheduled single-choice/multiple-select quizzes with difficulty tags. Managers can publish a course after it has a published lesson and enroll active student roster records. Students can read published lessons, download published materials, and record completion only when their linked student profile has an active course enrollment. Objective answers are scored server-side; start/close windows, timers and attempt limits are enforced by the API. Students and instructors can review newest-first paginated submitted quiz history within each quiz; staff can view aggregate quiz and assignment outcomes, teachers only for their published courses, and student identities are omitted from aggregate reports.
- Course editors can create, rename and delete course-scoped question banks; search, paginate, add, edit and remove bank questions; and snapshot selected questions into draft quizzes. API checks enforce the editor's course access, block cross-course imports and duplicate imports, and keep answer keys out of student quiz responses. Editing or deleting a bank item does not alter questions already copied into quizzes; detailed bank change history remains open.
- Course quizzes support teacher-reviewed written-response questions alongside automatically scored objective questions. The API stores student answer text separately from per-question grades, feedback and review metadata; scores remain marked pending/partial until every submitted written answer is reviewed. Course editors alone can grade, and aggregate averages exclude attempts awaiting review. Web, student/parent results and Expo views show review status.
- Objective quiz drafts can set a proportional negative-marking rate and pass percentage. The API penalizes answered wrong objective questions by points × rate, leaves blank answers unpenalized, clamps the total score at zero, and defers pass/fail while written answers are awaiting review.
- Admin, management, teacher, educator, student, and parent workspaces now include a paginated Documents/Study materials library. Server filtering limits staff to their tenant or owned courses, students to published files from active enrollments, and parents to published files for actively enrolled children linked by an explicit guardian record; private drafts and unrelated courses remain hidden.
- Independent educators can now manage courses, lessons, learner rosters, assignments, quizzes and manual meeting schedules from their connected dashboard. Management Performance opens aggregate course assessment reporting.
- The mobile Admin and Management workspaces now show the first five active students and teachers, server-reported active roster totals, today's organization-timezone attendance report with section rates, and aggregate published-course completion summaries with the top five courses. These use the existing role-checked organization APIs and report no learner identities. Mobile TypeScript and Android export passed; other mobile reports and approvals remain open.
- The allowlisted Super Admin can review live platform metrics, search/filter organization and user directories, suspend/reactivate organizations with a required reason, and review a paginated audit history of those status changes. Suspension removes the tenant from member organization selection and access; reactivation restores it. User directory responses omit passwords and tokens; authenticated live platform dashboards no longer display demo-only summary cards. Account changes, role configuration, broader audit coverage and support tools remain open.
- Documentation audit reconciled architecture, schema, decision, business, software, security and role descriptions with the implemented tenant workflows and platform organization controls. Reverification on 19 November 2026: web typecheck, ESLint and production build passed; 14 public routes prerendered.
- Public contact enquiries are rate-limited, consent-checked, honeypot-filtered, persisted, and optionally sent to a configured inbox. A verified allowlisted operator inbox supports filters/status tracking and sends plain-text replies through the configured mailer; the enquiry record stores responder/time but not the reply text. The public form reports whether notification was sent.
- Admins, management, and independent educators can create tenant-scoped INR fee receivables and record partial/final receipts already received. Students and linked parents can read their own fees; balances cannot be overpaid. Staff also have an aggregate finance report for issued, received, outstanding, overdue balances, and date-filtered recorded receipts. No external payment is initiated.
- Admins/management can schedule class and management meetings using manual HTTPS links; teachers can schedule assigned class meetings, while students and linked parents see only their enrolled/linked classes. Overlap checks and cancellation are persistent; provider room creation is not connected.
- The dashboard notification bell lists and marks recipient-owned notifications within the active organization. Users can control in-app announcement, meeting, and fee notices; delivery honors those settings, which default to enabled. Fee notice text omits amounts and fee titles. Email/push delivery and retention policies remain open.
- Student and parent dashboards now show submitted quiz scores and graded assignment feedback. Parent result access is restricted to the selected active child linked through a guardian record; response payloads omit submissions and quiz answers.
- Student “My progress” and parent “Academic progress” now display per-course and overall lesson completion from active enrollments in published courses, scoped to the signed-in learner or selected linked child.
- Parent “Homework” now lists published assignments for the selected linked child with due date, pending/overdue/submitted/graded status, score and feedback; written answers remain private.
- API and web setup/auth configuration is documented in `.env.example` files and `apps/api/README.md`.
- Multi-organization users can reopen the verified membership chooser from the dashboard workspace control. The selected organization is saved to the user's account and restored after a web reload; invalidated memberships do not restore and organization deletion clears the preference.
- The Expo SDK 56 mobile app in `apps/mobile` uses the shared Sanctum API, Expo SecureStore token persistence, account-wide preferred membership selection, role-scoped summaries, published lesson reading, student/parent profile, attendance, homework, course-progress and result-history reads, family-scoped fee records, student assignment submissions, scoped teacher grading, timed quizzes/results, notification read receipts, teacher attendance registers scoped to assigned sections, and role-scoped meeting details/join links. Android JavaScript export is verified; Android and iOS native toolchains/device builds are not available in this workspace.

Admin/management/educator views are organization scoped, teachers see their published courses, students see their own activity, and parents see only explicitly linked children. Demo dashboards label sample activity; the dashboard date now reflects the current client date.
