# Known Issues and Open Work

- [ ] Full client/API session verification has not been completed against a persistent local database and configured email transport.
- [ ] Workspace event emails are tested as queued jobs but remain disabled by default; configure an approved mail transport and a persistent queue worker, then verify delivery in a non-production environment before enabling.
- [ ] No automated component suite exists. Playwright Chromium E2E covers public course discovery, mocked contact submission, mobile navigation/overflow, all 19 public/account routes at 320/1440 px, all seven dashboard previews at 320/768/1440 px, mocked account UI state, and real local registration/verification/session sign-in against an isolated SQLite database. A full authenticated dashboard/mobile visual review remains open. Start the current local preview with `npm run dev:stack`; its web and API URLs are printed by the launcher.
- [ ] Platform operators can suspend/reactivate organizations with an audited reason and read the resulting status-change history. Organization creation/editing, account changes, role configuration, audit coverage beyond organization status, detailed reports, subscription controls, and support tools remain unfinished.
- [ ] `public/sitemap.xml` currently uses a reserved `.example` host; replace with the approved canonical domain before launch.
- [ ] Contact enquiries are persisted and can notify a configured mailbox; a verified allowlisted operator can send replies through the configured mail transport. The enquiry record stores only response time/operator, not reply content. Local log mail transport may write message bodies to the API log; retention cleanup remains open.
- [ ] Fee records support staff-entered INR receivables and receipts, paid expense tracking, and CSV statement matching with balance checks and duplicate-statement protection. There is no payment gateway, refund workflow, idempotency key, or finance-specific role.
- [ ] Meetings now support consent-attested staff uploads of private MP4/MOV/WebM files (up to 50 MB) or HTTPS recording links, publication to enrolled learners/linked families, withdrawal and access-checked downloads. The app does not capture Google Meet streams or provision provider rooms; reminder delivery, participant invites, a reviewed retention/deletion policy and production durable-storage configuration remain open. The consent checkbox records a staff attestation and is not a participant-consent collection workflow.
- [ ] Local registration and resend-verification responses expose a short-lived signed link in the auth screen; real verification/reset inbox delivery still depends on configuring an email transport.
- [ ] The announcement workspace can open manually prepared WhatsApp chats; outbound delivery, contact synchronization, and message tracking are not provided. Opt-in workspace emails are queued and track per-recipient status, but real delivery and push still require configured providers.
- [ ] Sample courses and provisional plan scope/pricing are not commercial offers.
- [ ] Privacy/terms/cookie/acceptable-use/refund copy is draft material pending legal review.
- [ ] Organization invitation email uses the configured mail transport; local development logs messages, so SMTP or another delivery service must be configured for real inbox delivery. Persistent preferred-organization selection is implemented; detailed policy-based resource permissions remain.
- [ ] The latest full Laravel suite passes on SQLite (149 tests / 1,215 assertions). The exam-section, Batch Master, notification preference, notification-delivery, Branch Master, Fee Category, organization access audit, branch-assignment, and meeting-recording migrations have not yet been rerun on PostgreSQL 17. The hosted PostgreSQL 16 CI job has not yet run; production/Render database provisioning remains unverified.

- [ ] Academic ERP is partial: branches are assigned to classes, students and teachers; class branch consistency, roster filters and compatible branch-specific teaching assignments are validated. Sessions, sections, searchable/filterable batches, subjects, rosters, teacher/subject/section/session assignments, invitations, direct guardian-link management, teacher-scoped attendance, timetable, student/parent attendance and result views, attendance/course-progress reports, aggregate enrollment placement, teacher workload, manual finance/expense summaries and CSV bank statement reconciliation are implemented.
